# Moonstar Insurance CRM: Email System Upgrade Report

This document outlines the end-to-end upgrade of the Email Template System. The primary objective was to replace a static, hardcoded email flow with a highly dynamic, database-driven templating engine.

---

## 1. Architectural Overview

The new system bridges the existing Postgres (`email_templates` table) with the existing Microsoft Graph API (`/api/send-email`), while introducing a robust new intermediate layer: **The Email Generator**. 

Instead of manual text areas with disjointed variables, the CSR team now has a dynamic interface that parses HTML templates on-the-fly, requests missing variables based on the exact template chosen, and allows for last-minute HTML adjustments in a live preview.

### Core Architecture Rules Honored:
- **Zero Database Schema Changes:** Relied exclusively on the existing `email_templates` table and fields.
- **Zero Backend Microsoft Graph Modification:** The Graph API integration remains completely untouched.
- **Backward Compatibility:** Ensured old form-based processes remain intact if the new custom payload is not utilized.

---

## 2. New Components Built

### A. The Email Generator Interface (`components/email/EmailGenerator.tsx`)
A brand new React component was created to act as the "control center" for the CSRs.
- **Dynamic Unlocking:** Automatically hides configuration fields until a template is selected to prevent CSR confusion.
- **Context-Aware Inputs:** Displays completely different input sets depending on the template (e.g., hiding "Policy Breakdown" tables unless the template explicitly requires a breakdown of multiple premiums/policies).
- **Array Management UI:** Built a highly reactive policy-building table to dynamically insert, manage, and calculate new carriers, old carriers, and premiums.
- **Live HTML Preview:** Any change inside the setup GUI triggers an immediate regex-rebuild of the raw HTML, allowing the user to view exactly what the client will receive.

### B. The Templating Engine (`lib/emailTemplating.ts`)
A dedicated templating processor to replace variables dynamically inside the HTML.
- **Complex Replacements:** Accurately formats dates, masks credit card numbers (e.g. `{{card_last_4}}`), correctly calculates premium savings differences (`{{savings_amount}}`), and maps default carriers.
- **Conditional Policy Table Generation:** Includes specialized helper functions (e.g., `buildPolicyRows`) that loop through user-provided policy arrays to inject strict `<tr>` rows directly into the HTML variables `{{policy_breakdown}}` and `{{savings_breakdown}}`.
- **Stringent Mapping:** Supports 11+ custom variables derived from the HTML reference point.

## 3. Files Modified & Refactored

### A. Lead Send-Form (`app/(dashboard)/csr/leads/send-form/page.tsx`)
- **Integration:** Replaced the legacy manual forms with the new `<EmailGenerator />` component.
- **Dropdown Fixes:** Ensured both "Form Type" and "Email Template" are clearly visible to govern flow logic. Restored missing HTML dropdown tags.
- **Logic Overhaul:** Refactored the `handleSend` function to support an optional Intake Form generation. If the selected email template does not require a form link, the API call is allowed to proceed smoothly without silently aborting the operation.

### B. The Send API (`app/api/send-email/route.ts`)
- **Validation Bypass:** Updated the endpoint requirements to prioritize the new system. The standard `<formType>` and `<intakeId>` requirements are now ignored if a valid `customBody` (from our new Generator) is passed in the payload.
- **Payload Structuring:** Ensuring the raw HTML `customBody` generated by the frontend completely overrides the database `body` inside the Graph API payload structure.

---

## 4. Current Work Flow for CSRs

1. Navigate to `/csr/leads/send-form?id=...` via existing pipeline buttons.
2. Observe the "Email Template" and "Form Type" dropdown menus.
3. Upon selecting an **Email Template**, the `EmailGenerator` unlocks visually.
4. The CSR enters required data (Target carrier, policy amounts).
5. The Live Editor rebuilds the HTML immediately.
6. Hitting **"Send Initial Email"** POSTs the data payload asynchronously to `/api/send-email`, bypasses legacy intake requirements, fires it through Microsoft Graph, and redirects the CSR back to their lead board.

---

## 5. Security & Maintenance Points

- **Templating Rules:** If a new exact template must be added the `email_templates` database, any placeholder requiring *calculation* (such as savings amounts) must be mapped into `lib/emailTemplating.ts`. Standard string replacements map automatically.
- **Database Alignment:** The system filters out "Umbrella" named templates automatically to reduce clutter, as requested by legacy specifications.
- **Error Capturing:** If `formType` is ever required but generation fails, the UI throws a dedicated Toast alert instead of failing silently.
